# Arizona 42Loader

**Unofficial Lua scripting loader for Arizona RP Mobile (iOS)**

> Архивный проект. Разработка приостановлена.

42Loader — экспериментальный сторонний Lua-загрузчик для iOS-версии Arizona RP Mobile, вдохновлённый архитектурой MoonLoader для GTA: San Andreas.

Цель проекта — создать собственную систему загрузки и выполнения Lua-скриптов непосредственно внутри игрового процесса Arizona Mobile, предоставив пользователям возможность использовать пользовательские скрипты, помощники и расширения.

## Статус проекта

**ARCHIVED / DISCONTINUED**

Разработка 42Loader остановлена 26 ноября 2026 года.

Причина остановки: разработчик оригинального лаунчера Arizona Mobile добавил собственную вкладку «Модификация». Её функциональность оказалась более полноценной и удобной, чем планировалось реализовать в 42Loader.

В результате дальнейшая разработка отдельного загрузчика потеряла практический смысл.

К сожалению, проект не удалось довести до запланированного финального состояния.

Репозиторий сохранён в архивных целях. Он может представлять интерес для разработчиков, изучающих Lua-интеграцию в iOS-приложения и модификацию игровых клиентов.

## Архитектура проекта

42Loader построен в виде динамической библиотеки `LuaLoader.dylib`, предназначенной для работы внутри процесса Arizona RP Mobile.

В отличие от отдельного приложения, загрузчик должен взаимодействовать с игровым клиентом непосредственно из его адресного пространства.

### Принцип работы

1. **Инициализация**

   После загрузки `LuaLoader.dylib` выполняется инициализация загрузчика и необходимых компонентов.

2. **Запуск Lua Runtime**

   Создаётся Lua 5.4 state, подготавливаются стандартные библиотеки и дополнительные функции загрузчика.

3. **Подготовка окружения**

   Регистрируются API загрузчика, необходимые для взаимодействия скриптов с игровым окружением.

4. **Загрузка скриптов**

   Загрузчик обращается к пользовательской директории и обнаруживает Lua-файлы.

5. **Выполнение**

   Скрипты запускаются в Lua Runtime. Для асинхронных операций и отложенного выполнения предусмотрена система корутин.

6. **Отображение интерфейса**

   Для пользовательских интерфейсов используется Dear ImGui с рендерингом через Metal.

## Файловая структура

Пользовательские данные размещаются в директории:

`Documents/lua_loader/`

```text
lua_loader/
├── scripts/
│   └── example.lua
├── config/
│   └── ...
├── lib/
│   └── ...
└── loader.log
```

- `scripts/` — пользовательские Lua-скрипты.
- `config/` — конфигурационные файлы.
- `lib/` — дополнительные библиотеки.
- `loader.log` — журнал работы загрузчика.

## Основные компоненты

### Lua Runtime

В качестве интерпретатора используется Lua 5.4.

Реализуется собственная среда выполнения скриптов, ориентированная на совместимость с подходом MoonLoader.

### Coroutine Scheduler

Для выполнения отложенных операций и работы с корутинами используется планировщик, интегрированный с циклом обновления через `CADisplayLink`.

Предусмотрена концепция функций `wait()` и отдельных потоков выполнения скриптов.

### Dear ImGui

Интерфейсная система построена на Dear ImGui.

Рендеринг осуществляется через Metal, что позволяет использовать интерфейс непосредственно поверх игрового окружения.

### API

В проекте предусмотрены интерфейсы для работы с:

- Игровыми командами и чатом.
- Диалогами.
- HTTP-запросами.
- Конфигурациями INI (`inicfg`).
- JSON.
- Кодировками CP1251 и UTF-8.
- Пользовательскими интерфейсами ImGui.
- Взаимодействием с игровым окружением через пространство имён `az`.

## Сборка

Проект ориентирован на iOS ARM64.

Основная динамическая библиотека:

`LuaLoader.dylib`

Для автоматизации сборки используется GitHub Actions.

В процессе сборки применяется Objective-C++ и компиляция с поддержкой ARC (`-fobjc-arc`).

Результатом является динамическая библиотека для интеграции с iOS-клиентом.

## Ограничения

42Loader не достиг полной совместимости с оригинальным MoonLoader.

Lua 5.4 отличается от LuaJIT, который используется в оригинальной экосистеме MoonLoader. Поэтому совместимость с некоторыми существующими скриптами требует отдельной реализации API и дополнительных библиотек.

Не все задуманные возможности были доведены до рабочего состояния.

Проект следует рассматривать как экспериментальную разработку, а не как готовый продукт.
